# Internal statement billing: phase 6 manual test

Use a non-production MariaDB database with Flyway migrations V42 and V43 applied. Configure an internal M-Pesa provider tenant, a current subscription with a nonzero statement price, and a user with `CREDIT_CHECK_RUN` and `CREDIT_CHECK_VIEW`. Use a super admin with `TENANT_SUBSCRIPTION_MANAGE` for subscription changes and billing retries. Follow `statement-subscription-phase-5-test.md` to set policies and fund the subscription.

1. Under `CHARGE_EVERY_ANALYSIS`, upload a synthetic PDF and start analysis. Poll `GET /api/v1/applications/{applicationId}/statement-analysis`. Once transactions are extracted, confirm `analysis.billingStatus` is `CHARGED`, the result is in manual review, and the subscription's balance is reduced by the price captured when the analysis was submitted. Check `GET /api/v1/internal/tenants/{tenantId}/subscriptions/current/ledger` and `/current/usage`: there must be one `STATEMENT_SUCCESS` debit whose reference ID is the analysis ID, with the captured currency and amount. Failed extraction or zero extracted transactions creates no debit.
2. Submit a new analysis for the same document when permitted by the application workflow; it gets a new ID and is charged again under `CHARGE_EVERY_ANALYSIS`. Reprocessing the same analysis ID must not produce a second debit or second review. Test concurrent completion in a MariaDB test environment.
3. Set `CHARGE_ONCE_PER_DOCUMENT`. After a successful charge for the document, request a new analysis of that same LOS document. It should complete with `billingStatus: WAIVED` and no additional debit, even if the earlier debit was on an older subscription. A reuploaded copy has a different document ID and is treated as a new document.
4. With negative balance allowed, verify that a successful analysis can debit below zero. With negative balance disabled, normally admission rejects an insufficient balance. To exercise a balance change after admission, start a queued analysis, reduce the available balance through an authorized existing charge before completion, and confirm the extracted result is retained with `billingStatus: PENDING_FUNDS` and no debit. Top up the **captured** subscription, then call `POST /api/v1/internal/tenants/{tenantId}/subscriptions/{subscriptionId}/statement-billing/{analysisId}/retry`. Confirm `CHARGED`, one debit, and that retrying again does not debit again. Retry is manual; a top-up does not trigger it automatically.
5. Change the plan price or cancel the subscription after submission but before completion. The original subscription and captured amount are charged. Inspect an inactive subscription's ledger at `GET /api/v1/internal/tenants/{tenantId}/subscriptions/{subscriptionId}/ledger`. If the subscription's current plan currency differs from the captured currency, billing enters `CURRENCY_MISMATCH` rather than mixing currencies; an administrator must correct the configuration and retry. Analyses created before V42 without captured terms enter `MISSING_TERMS` and require manual reconciliation; no price is guessed.
6. Verify Cladfy's existing processing and billing are unchanged, and tenant users cannot invoke the platform billing retry endpoint. Cross-tenant analysis and ledger access must be rejected.

Tests:

```powershell
.\mvnw.cmd clean test "-Dtest=InternalStatementBillingServiceTest,StatementSubscriptionEligibilityServiceTest,StatementSubscriptionPolicyTest,SubscriptionBillingLockTest,InternalMpesaCompletionServiceTest,InternalMpesaProcessingServiceTest,StatementAnalysisServiceTest,StatementAnalysisProcessingServiceTest,StatementAnalysisResponseApiTest,CladfyStatusPollingServiceTest"
```

The focused tests do not prove MariaDB locking, migration compatibility, or automatic recovery from a process restart. Run the concurrency and migration checks against MariaDB. Durable job recovery remains phase 7.
